# 代码组织

GUI 与命令行共享工具预设与宝可梦准备逻辑；游戏模块各自保留线路格式与时序，共享组件置于游戏目录之外。

| 位置 | 职责 |
| --- | --- |
| `pokeldn/app/` | 工具目录、参数组装、解析器检查、设置、路径与子进程 |
| `pokeldn/popup.py` | 程序在应用中显示的[弹窗](gui.md#pop-ups)；`pokeldn/app/popups.py` 决定显示哪个 |
| `pokeldn/pokemon.py` | PKHeX 服务、导入、最终提供验证与接收文件 |
| `pokeldn/gifts.py` | 共享[神秘礼物文件](gifts.md)封装、读取、写入与原生转换 |
| `pokeldn/for_receiver.py` | 交换期间为主机存档制作的宝可梦：神秘礼物（[为接收玩家制作](gift_simulated.md#made-for-the-receiving-player)）或作为原始训练家给接收方的提供（[原始训练家](gui.md#original-trainer)） |
| `services/pkhex/` | 固定版本 PKHeX.Core；合法遭遇生成与兼容性检查 |
| `pokeldn/ldn/` | 无线电传输、IP、Pia、可靠性与信道表 |
| `pokeldn/online/` | [网络交换](online.md)：中继、匹配与加密伙伴信道 |
| `pokeldn/gba/` | GBA 无线链路协议 |
| `pokeldn/gen8.py`, `pokeldn/gen9.py` | 共享宝可梦记录编解码器 |
| `pokeldn/<game>/` | 游戏标识、消息、状态机与协议变体 |
| `pokeldn/launcher.py` | 所有 `bin/` 启动器共享的标志（`--keys`、`--phy`、`--capture`、Linux 网卡名、`--ip-host`/`--our-ip`）与扫描网络的单行描述 |
| `bin/` | 解析器与会话编排 |
| `gui/` | 视图、控件、主题与面板控制 |

应用同一时间仅运行一个会话，因为一块开发板仅服务于一个进程。在另一工具上点击启动会停止正在运行的会话，等待其退出后再启动；启动也会等待正在进行的刷机完成。

## 宝可梦准备

每个交换启动器在打开无线电之前，都会通过 PKHeX 服务处理提供的文件。不兼容的格式、不可用的物种和非法的最终记录会被拒绝。会话的训练家身份永远不会覆盖导入宝可梦的原始训练家。

| 行为 | 规则 |
|---|---|
| 分析不完整 | `LegalityAnalysis.Parsed` 为 false 时在服务锁下重启助手并重试一次；第二次失败则抛出异常 |
| 全新身份 | 可选生成新 PID 和加密常量；若在此下非法则保留原有并记录 `the offer kept its own PID` |
| 异色、单一性别 | 从遇到处请求，因此第三代 PID 保持其 RNG 相关性 |
| 随机生成 | PID、个体值和野生栏位的等级，每个遇到最多八次生成 |
| 进化形态 | 在无遇到匹配捕获时提升至进化等级；无性别（如掉壳忍者）取进化后性别，遇到的形态不存在（如葱游兵）取形态 0 |

因等级或物种变更而失败的记录会按顺序修复，每步基于上一步；保留首个合法结果：

1. 仅限 HOME 活动（剑／盾中的捷拉奥拉、梅尔梅タル）在设置为「已制作」时获得 HOME 标记（[HOME 标记设置](gui.md#the-home-tracker-setting)）。
2. 重新适配招式、遗忘招式、TM/TR 记录标志、额外招式与大师标志，以及传说 阿尔宙斯的体型。
3. 进化记录的特性在其捕获栏位中刷新。此步必须在重新适配之后（传说 Z-A 中的赛富豪）。
4. 无处理训练家的记录获得 `POKELDN`。
5. 计数进化（急击、受到伤害、愤怒拳使用次数、金币）从其计数开始。
6. 晶灿钻石／明亮珍珠中的美貌进化（米洛耶塔，170）设定该美貌度及其波芬所暗示的最低光泽度。

无法满足的请求会附带理由被拒绝。纯净构建仅在以下情况失败：晶灿钻石／明亮珍珠 2 只（时拉比、代欧奇希斯），剑／盾 2 只（蒂安希、梅尔梅タル），传说 Z-A 1 只（米洛耶塔，其游戏记录拒绝比赛属性），朱／紫 31 只（仅限 HOME 的传说宝可梦，以及 PKHeX 未给出第九代进化的 Ayashishi）。

未指定形态的请求取首个可构建的形态。仅在后续形态存在的物种：

| 游戏 | 物种 | PKHeX 可构建的形态 |
|---|---|---|
| 剑／盾 | 基格尔德 | 10%-C、50%-C（能量构造） |
| 剑／盾 | 梅尔梅タル | 原色、活动 |
| 传说 阿尔宙斯 | 起源盖欧卡 | 起源 |
| 朱／紫 | 月夜黑马 | 血月 |
| 传说 Z-A | 基格尔德 | 10%-C、50%-C、完整 |
| 传说 Z-A | 散华、毒蛾 | 花园、草原 |
| 传说 Z-A | 比比鸟 | 花园、草原、海洋 |

### 遇到顺序

构建按版本逐个尝试 PKHeX 的遇到（`EncounterMovesetGenerator`），玩家自己的版本优先，每个版本内按类别，每类截取前 80 个遇到：

| 顺序 | 类别 | 由此构建的记录 |
|---|---|---|
| 1 | 野生栏位 | 在该栏位地点和等级捕获，任意可捕获球 |
| 2 | 固定遇到 | 赠送、传说、团体战或极巨巢穴宝可梦 |
| 3 | 游戏内交换 | NPC 的宝可梦 |
| 4 | 蛋 | 孵化，继承父母传递的球 |
| 5 | 神秘礼物 | 在所有其他类别和版本之后，因为活动的固定 PID 会使新 PID 的提供非法 |

去吧！皮卡丘和去吧！伊布在自己的版本后还会尝试 GO 版本：GO Park 复合设施存放从 Pokémon GO 带来的宝可梦，包括梅尔坦、梅尔梅タル和阿罗拉形态。那里的一个遇到选择是 PKHeX 列出的每个时间窗口上的一种 GO 遇到类别（野生、团体战、调查和其余）。

低于进化等级的进化宝可梦先在 100 级测试，然后二分查找最低合法等级。朱／紫中的苹果龙仅在分散的等级合法。

存档会清除接收到的、其原始训练家姓名、ID 和性别与自己相同的宝可梦的处理者（[交换写入接收记录的内容](za.md#what-the-trade-writes-into-a-received-record)）。PKHeX 仅在有处理者（如玛机雅娜等 HOME 赠送）且原始训练家是玩家时才采用该构建，并以原始训练家 POKELDN 和玩家作为处理者构建；「让我成为它的原始训练家」会拒绝此类文件。

### 提供选项

构建可请求形态、性格、特性、性别、携带道具、球、亲密度、最多四个招式、个体值和努力值、遇到、在传说 阿尔宙斯和传说 Z-A 中是否为阿尔法、马奶蕾的甜味、在剑／盾中超极巨化因子和极巨等级、在朱／紫中太晶属性。形态、遇到和阿尔法缩小遇到搜索范围；性格、特性、性别和个体值进入遇到判定标准。当遇到生成的结果不同，记录会像玩家操作那样修改：

| 差异 | 修改 |
|---|---|
| 性格 | 薄荷，第八代起 |
| 特性 | 特性胶囊或特性贴片 |
| 请求个体值为 31 | 超级训练，100 级（第七、八代）或 50 级（第九代） |
| 形态 | 设定在玩家可改变形态的物种上，如洛托姆 |

携带道具、球、亲密度、努力值、甜味、超极巨化因子、极巨等级和太晶属性在构建后设定，如同极巨汤、极巨糖和太晶碎片。甜味是马奶蕾的形态参数，0 草莓到 6 丝带；太晶属性是覆盖字节，星辰 99（`TeraTypeUtil.SetTeraType`）。第三、四代努力值超过 100 需要遇到后获得经验，因此记录获得 1 点经验。传说 阿尔宙斯的努力等级按游戏显示取值，存储前减去 IV 偏移（IV 20 为 1，26 为 2，31 为 3）。

亲密度属于原始训练家。接收方主机仅在玩家是原始训练家时保留它，因此设置中的[你的训练家](gui.md#your-trainer)必须是玩家；各标题的交换页面说明交换会重写什么。火红／叶绿对每个接收的非蛋宝可梦设定 70 [trade_scene.c:1071]。

| 选项 | 列出条件 |
|---|---|
| 球 | PKHeX 允许其用于至少一个遇到 |
| 阿尔法 | 传说 阿尔宙斯或传说 Z-A 有该物种的阿尔法遇到（`IAlphaReadOnly.IsAlpha`） |
| 特性 | 存在携带它的合法构建；传说 Z-A 列出无 |
| 携带道具 | 该游戏已发布的携带道具；去吧！和传说 阿尔宙斯无 |
| 努力 | EVs 单项 252、总计 510；去吧！为 AVs 单项 200；传说 阿尔宙斯为努力等级单项 10 |
| 甜味 | 马奶蕾，在记录保留形态参数的游戏中 |
| 超极巨化 | 该物种和形态的 `Gigantamax.CanToggle` |
| 极巨等级 | 剑／盾，除捷拉奥拉、藏玛然特、穆尔纳 |
| 太晶属性 | 朱／紫，太晶属性可变的物种（`TeraTypeUtil.CanChangeTeraType`）；18 种属性和星辰 |

个体值、努力值和亲密度标签行上的 Max 按钮原地填充该组：个体值全六项 31，亲密度 255。努力值将每项填至上限；总计低于 510 时，物种的两个最高基础属性得 252，第三高得剩余 6。

### 选择遇到

`encounters` 列出该物种和形态可来源的每个遇到，按[遇到顺序](#encounter-order)分组：同一地点同一版本的一种遇到类别，其所有栏位和等级在一起，或一张神秘礼物卡（`EncounterKey`）。每组携带地点名称（`ILocation.GetEncounterLocation`，赠送卡的标题）、等级范围、遇到时物种为进化前时的该物种、以及是否可异色。给定组键的构建仅尝试该组；构建的回复给出其 `encounter_place`。

[遇到顺序](#encounter-order)中首个能合法承载所有请求的遇到被保留；否则拒绝并指出首个无法承载的请求。

### Showdown 套装

导入粘贴通过 `ShowdownParsing.GetShowdownSets` 读取 Showdown、Smogon 或 PKHeX 套装，支持 PKHeX 导出的任何语言及其拼写。无 `Level:` 行视为 100；`IVs:` 中缺失的个体值视为 31。

| 套装指定 | 结果 |
|---|---|
| 不可读行，或游戏缺少的物种、形态、特性、道具、招式，努力值超 510 | 拒绝；不填充任何内容 |
| 朱／紫的太晶属性；剑／盾的超极巨化和非 10 的极巨等级 | 设定（[提供选项](#offer-options)） |
| 其他游戏的太晶属性、超极巨化或极巨等级，隐藏力量属性；去吧！或传说 阿尔宙斯的努力值；传说 Z-A 的特性 | 忽略，附带备注 |
| 无 `IVs:` 或 `Friendship:` 行 | 使用遇到自带的值 |
| 交换队列中的多套装 | 从粘贴选择器逐个交换，不超过队列上限；任一拒绝则拒绝整个粘贴 |
| 队列外的多套装 | 首个填充表单 |

剑／盾神秘礼物验证 WC8 印章，并用 PKHeX 核对物种、形态、招式和道具；自定义卡是分发，非官方活动。

### 去吧！连接代码

去吧！主机的代码为三个栏位，各从主机的十个选择宝可梦中选取，作为三个英文名以逗号分隔传给 `--code`。启动等待直到三者全部设定。

### 交换队列

在一个座位上完成多次交换的工具最多接受六只宝可梦，按顺序提供：

| 工具 | 提供方式 | 最后之后 |
|---|---|---|
| 火红／叶绿主机和加入 | 队伍文件，`--trades N` | 主机拒绝（`PLAYER_CANCEL_TRADE`）并等待取消和确定；加入方取消 |
| 去吧！主机 | `--offer`，然后 `--next-offer` | 不再响应交换（`pokeldn/lgpe/trade.py`） |
| 去吧！加入 | `--offer` 重复 | 不再响应交换 |
| 晶灿钻石／明亮珍珠 | `--offer` / `--trade-template` 重复 | 最后一只再次 |
| 传说 阿尔宙斯 | `--trade-box-record` / `--offer` 重复 | 最后一只再次 |
| 朱／紫 | `--trade-offer` 重复 | 无后续消息（`pokeldn/sv/trade.py`，`done`） |
| 剑／盾 | `--offer-file` 重复 | 最后一只再次 |
| 传说 Z-A | `--trade-offer` 重复 | 最后一只再次，使用 `--fresh-pid` 生成新 PID |

每次完成的交换调用 `pokeldn.ldn.show_done()`，闪烁 LED 并打印 `[done] trade N complete`；会话面板计数该行。每个交换主机和加入方仅在交换完成后写入接收到的宝可梦，从不在主机提供时写入：玩家仍可撤回提供，应用将每个文件存入接收箱。第 1 次以上的交换写入输出路径并加后缀：`_tradeN_` 加物种（火红／叶绿）、`.N`（朱／紫）、`_N`（晶灿钻石／明亮珍珠主机）、`-N`（传说 Z-A、剑／盾）。

### 交换回

`--trade-back`，在每个交换主机和加入方上（应用的「送回」开关），在每个排队交换后追加一次交换，提供主机刚发送的宝可梦，使通过交换进化的宝可梦在主机上进化。玩家在第二次交换中提供我们的宝可梦回去。交换后主机不发送任何内容，直到玩家再次交换（零售版朱的最后状态 `b90101b902b90280800100`，随后 26 秒静默并在玩家退出时离开），因此返回轮会向玩家显示 `trade-back` 状态卡提示再次交换。`pokeldn/trade_back.py` 保存顺序：

| 交换 | 提供 |
|---|---|
| 1, 3, 5, ... | 排队提供 1, 2, 3, ... |
| 2, 4, 6, ... | 上一次交换中主机发送的记录，字节级复制 |

返回的记录从不接受 `--fresh-pid` 或任何其他提供编辑。在最后一个排队交换后停止的启动器会在两倍数量后停止；重复提供最后一只的会持续交替。

| 启动器 | 记录如何返回 |
|---|---|
| 原生主机 | `TradeBack` 代替在线伙伴（`pokeldn.online.link.Partner`）：`done` 前主机的最后提供成为下一轮的记录 |
| 火红／叶绿主机和加入 | 每个提供的队伍栏位再次提供；TradeMons 已将接收的宝可梦放入 [trade_scene.c:1054-1083]。会话最多 12 次交换 |
| 原生加入方 | `Rounds` 在启动器自己的提供路径中选择每次交换的记录 |

由 `bin/frlg_trade_host.py --over-ip --trade-back` 主机的模拟法语火红在交换 1 中交换凯西，交换 2 中取回并进化为胡地；存档保留了合法的胡地。由 `bin/swsh_host.py --ip-host --trade-back` 主机的模拟盾在交换 1 中用提供的大岩蛇交换武道熊师，交换 2 中用大岩蛇取回武道熊师并按 B 离开。

`--trade-back` 拒绝 `--online`、为接收玩家制作的赠送、团体战、极巨巢穴和联合环模式。神秘礼物 - 模拟从不提供它。

### 主机显示的宝可梦

`--save-shown FOLDER`，在每个交换主机和加入方上（应用的「保存主机显示的宝可梦」开关，在所有选项中），在交换期间主机发送的每个宝可梦记录到达时写入，在任何确认之前。玩家退出时保留宝可梦且文件保留，因此种子或合法性检查可在不交换的情况下读取宝可梦。`pokeldn.pokemon.save_shown` 命名文件为 `<game>-<encryption constant>.<ext>`（PK3 的 PID）；同一常量下再次发送的记录替换其文件。

| 标题 | 写入的记录 |
|---|---|
| 火红／叶绿 | 主机的整个队伍，三个队伍块到达后各解密为 100 字节 PK3；每次交换后队伍再次发送（`pokeldn.frlg.link.trade_runtime.shown_party`） |
| 去吧！ | 本轮提供类别上的每个提供 |
| 剑／盾 | 每个携带 PK8 的宝可梦交换消息 |
| 晶灿钻石／明亮珍珠 | 每个 `NetTradePokeData` |
| 传说 阿尔宙斯 | 每个交换箱记录，显示（光标）和提供 |
| 朱／紫 | 每个提供主体 |
| 传说 Z-A | 每个提供消息、预览（光标）和选择 |

应用写入接收箱旁的 `Shown` 文件夹；其中的内容不计为接收，也不进入存放箱。

### 结束运行

| 角色 | 结束条件 |
|---|---|
| 主机 | 至少一次交换后主机离开（`pokeldn.ldn.left_after_trade`） |
| 火红／叶绿主机 | 主机离开 |
| 加入方 | 主机关闭或移交角色；朱／紫、传说 阿尔宙斯和传说 Z-A 在无交换座位后重新搜索 |

`--seconds` 和 `--hold` 限制主机从不离开的运行时长。
`--hold-after-trade N`，在每个交换启动器的两个角色上，在最后一个排队交换后 N 秒离开座位或关闭会话（`pokeldn.ldn.hold_after_trade_over`）。

## 本地文件与发布

`host.local.toml`、密钥、备注、日志与构建产物均保留在本地；不读取生产环境默认值 `scratchpad/`。设置与已准备的礼物存放在平台的数据文件夹中，可通过 `POKELDN_DATA` 覆盖。清理通过 `pokeldn.app.storage` 运行（[本地存储](gui.md#local-storage)）。

打包器会捆绑受跟踪的运行时文件、PKHeX 可执行文件以及 ESP32、S3、C3 和 C6 的固件；缺少镜像会导致构建停止。Windows 构建保留标准流以供子进程日志使用，并隐藏控制台。

## 验证

```sh
pip install -r requirements-dev.txt
dotnet build -c Release services/pkhex -warnaserror
python -m pytest tests/ -q -W error -n auto --dist worksteal
```

CI 会在 Linux、macOS 和 Windows 上运行这些命令。发布构建会针对冻结后的可执行文件运行 `scripts/check_app.py`；该脚本无需密钥或开发板。
